Interaction flows — where Brio fails and how this design answers it

1 · Pose a bone (the core loop)

Select actor (sidebar row or click in world) → bone dots appear → click a dot → gizmo at the bone; drag to rotate, T/R/S to switch, Ctrl+Z undo. The world is the primary surface — the window is only for precision (scrubbers) and the long tail. Brio routes this loop through dense nested windows; here you never need to open one.

2 · Precision / multi-actor work

Double-click a bone or entity → compact detached window for it. Pop out any tab, pin it to its entity, repeat for a second actor — two Animation panels side by side. Unpinned windows follow selection, so one floating Transform panel can serve the whole session.

3 · Screenshot session (minimal UI)

Hide-UI toggle → hotbar only or nothing. Double-click brings back exactly the panel you need, Esc dismisses. No hunting for a re-open button — Brio's overlay toggle famously strands users.

4 · Scene setup

Sidebar groups (Actors/Cameras/Lights) each have a hover +: spawn actor, new camera, new light — creation lives where the created thing will appear, not in a separate spawn menu. Environment (time/weather/sky) is a tab, not a fourth window.

5 · Save / load / share

Library tab = pose/scene browser (grid + tags + ratings). Right-click any actor → Export pose; drag a pose from the library onto an actor in the sidebar to apply. Import options (body/expression, model transform) appear as a compact glass modal only when a choice is actually needed.

6 · Selection is always visible

Tabs are TYPED BY THE SELECTION: an actor offers Pose · Animation · Appearance; a bone just Pose; a camera its Camera tab; a light its Light tab — followed by the always-present scene tabs (Environment · Library) after a divider. Stable per entity type, so no per-frame widget soup; the breadcrumb shows what the tab is acting on. The sidebar is the only list of entities — panes edit the selection, they never repeat the list. With nothing selected, only the scene tabs remain and the content area shows an empty-state hint. Brio’s context-dependent widget soup is still the anti-pattern — typing by selection is coarse and predictable, not per-widget.

A — Studio: 280px scene sidebar + tabbed content region (Pose · Animation · Appearance · Camera · Light · Environment · Library). Every tab can pop out; detached windows pin to entities.

B — Palette (360px): identical components stacked — scene on top, row-resize splitter, tab strip with short labels. Same pop-out model.

C — Hidden: no window at all. Bone dots + gizmo + optional glass hotbar; double-click opens per-entity panels on demand.
