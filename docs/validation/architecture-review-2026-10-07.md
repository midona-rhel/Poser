## Proposed architectural changes

### 1. Make feature commands own mutation outcomes and history
UI surfaces should submit stable IDs and requested values to a feature command owner; that owner coordinates validation, writes, results, and history. Game adapters resolve native entities. The UI renders results through one notice policy. Use existing sessions and result-aware journal APIs; do not add a generic command bus or another journal.
Start with appearance and visibility: migrate fallible writes to `TrySet`/`RecordResult`, introduce one multi-target visibility command, then route sidebar, inspector, group and context-menu actions through it. Keep single-target and batch entry points under the same owner. A batch must explicitly define rollback versus partial success and preserve failed inverse recovery; do not blindly wrap every loop in an edit scope.
Acceptance: refused initial writes preserve history/redo; refused inverses do not advance the cursor; one multi-target action produces one entry; every surface has the same refusal behavior; stale generations never redirect writes. Once this vertical slice is accepted, audit other value sessions and migrate only those with the same fallible-write shape.

### 2. Make parent operations own child completion and cleanup
A scene operation should retain the identity and completion of every child it admits. Stopping a wait must not be mistaken for stopping work. Extend the existing operation receipts with an operation-scoped cancel/drain seam; keep MCDF's transaction and native guards as the execution owner.
Start at scene-to-MCDF admission: cancellation/timeout cancels only the matching operation, waits for terminal cleanup or exposes retained recovery ownership, and releases staged inputs only when no child still needs them. Then preserve aggregate outcomes in the existing ordered session teardown. Keep required cleanup ordering explicit rather than encoding it in subscriber construction order.
Acceptance: hold a child past its deadline, cancel between admission and execution, complete it late, replace the actor/session, and refuse cleanup. The parent cannot report successful completion while its child can still mutate; timeout cannot cancel a newer operation; incomplete cleanup retains an identifiable owner and evidence. Do not introduce an unbounded framework-thread wait.

### 3. Make views consume current state through explicit owners
ConfigurationService should remain the owner of configuration replacement/persistence. Consumers should read current settings through an injected service/accessor rather than retaining replaceable DTOs or finding a process-global instance. Keep UI disclosure, filters and window geometry local; keep mutation baselines and history in feature owners.
Start by removing ScenePane's cached library DTO, then audit captured nested settings and migrate static consumers as their features are touched. Preserve the existing reset/replacement behavior instead of changing it globally to hide one stale-reference bug. Extract MainWindow command routing along the feature boundary in change 1; split rendering only where a cohesive independent state owner emerges.
Acceptance: change library roots, reset configuration, change roots again, and verify saves/loads use current settings without recreating windows. Test two isolated configurations to expose hidden global dependencies. Follow the [current assembly boundaries](../architecture/product-and-boundaries.md#current-assembly-boundaries): UI consumes Application/Domain/Documents contracts and the host supplies runtime implementations; do not restore the reviewed checkout's retired host-UI/Core layout.

Atomic-store duplication remains a candidate only after recovery tests establish a smaller useful common boundary. Class length alone is not a finding.
